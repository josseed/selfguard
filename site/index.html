Attacks hit the ones you forgot.

You have dozens of projects on your laptop: side projects, old clients, agent worktrees, that tutorial from last year. When a worm like Shai-Hulud ships a compromised release, npm audit won't run itself and Dependabot doesn't know those folders exist. selfguard does.

How it works

Set it up once. It tells you on its own.

Alerts without asking

A watcher re-checks a repo seconds after its lockfile changes. A scheduled sync catches newly published advisories, and you get a "✓ fixed" when you clean one up.

Malicious packages first

OSV's OpenSSF malicious-packages feed outranks every CVE. A compromised release opens a dialog that stays on screen until you deal with it.

One fix per package

"Upgrade lodash to 4.18.0", not a wall of advisories. Direct or transitive, with the exact version that clears every finding.

Finds your projects

"Find my projects" searches your home folder, skips caches and cloud drives, and finds agent worktrees through their repos. cd into a project and it's registered.

Signal over noise

Only checkouts with recent git activity alert you. Old clones stay listed but quiet, except for malicious packages, which always speak up.

All your machines

Other Macs connect over Tailscale with a pairing code. Servers use SSH with a dedicated, read-only key. Alerts name the machine.

New in 0.18 · Agent guard

Your AI tools are part of the supply chain now.

Opening a repo shouldn't run someone else's code. selfguard reads, as plain data, the files that can: Claude Code project hooks, Cursor, Gemini CLI and Codex hooks, VS Code tasks that run on folder open, and hidden Unicode in CLAUDE.md, AGENTS.md and rules files.

  • MCP servers configured for Claude, Cursor, VS Code, Codex and more, without reading their secrets
  • GitHub Actions: compromised actions, unpinned refs, script injection
  • Urgent warnings (autorun tasks, hooks that download code) alert like malware

Meet Bastion

A 16-bit castle guard who acts out what changed.

He lives in the Mac app's dashboard and menu bar. One look tells you how your repos are doing.

Safe by design

Local-first. Nothing to trust but a lockfile.

name@version

Only the ecosystem, name and version of your locked dependencies go to the OSV.dev API. No paths, repo names or source code.

0 deps

Zero runtime dependencies, published to npm with provenance. It never executes code from your projects.

~/.selfguard

All state stays on your disk, readable only by your user. No account, no server, no browser dashboard.
